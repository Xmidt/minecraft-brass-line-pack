# The Brass Line — modpack repo

A Create-focused survival modpack for **Minecraft 1.20.1 / Forge 47.4.10**, managed with
[packwiz](https://packwiz.infra.link/). This repo **is** the pack: there are no jars in it, only
packwiz metadata (`pack.toml`, `index.toml`, `mods/*.pw.toml`, `shaderpacks/*.pw.toml`).
`README.md` is the player-facing documentation; this file is for working on the pack.

## How it is consumed

Everything is served from `https://raw.githubusercontent.com/Xmidt/minecraft-brass-line-pack/main/pack.toml`,
so **whatever is pushed to `main` goes live** on the next server restart / client launch.

- **Clients:** Prism Launcher instances run `packwiz-installer-bootstrap.jar` as a pre-launch
  command and pull `client` + `both` files.
- **Server:** itzg `docker-minecraft-server` under a Podman Quadlet user unit
  (`minecraft-brass-line`), with `PACKWIZ_URL` set to the URL above. It pulls `server` + `both` files.
  Restart: `systemctl --user restart minecraft-brass-line`.

Never push a half-finished change to `main`. A broken push breaks every player's next launch.

## Files

- `pack.toml`: pack name, MC/Forge versions, and the hash of `index.toml`.
- `index.toml`: hash list of every metadata file. Generated by `packwiz refresh`; never edit it by hand.
- `mods/<slug>.pw.toml`: one per mod: `name`, `filename`, `side`, download URL + hash, and
  `[update.modrinth]` / `[update.curseforge]` ids.
- `.packwizignore`: keeps `README.md`, `CLAUDE.md`, and git files out of the index.

## Side tagging (most important rule)

Every `.pw.toml` has `side = "client" | "server" | "both"`. Getting this wrong breaks things:

- **Client-only mods tagged `both` crash the dedicated server.** This happened with Controlify
  (commit f142b6f). Anything that touches rendering, input, controllers, shaders, or GUI only
  (Embeddium, Oculus, Entity Culling, Controlify, Mouse Tweaks, IPN, Controlling) → `client`.
- **Mods with content (blocks, items, entities, worldgen, recipes) → `both`.** If they're missing
  on either side, players can't connect or the world loses data.
- **Info mods that sync data from the server** (JEI, Jade, JourneyMap, AppleSkin) → `both`.
- **Server-only mods** (e.g. AntiXray) → `server`.
- A library's side must cover every mod that depends on it. If a `both` mod needs a library,
  the library must be `both` too.

packwiz often picks the wrong side from Modrinth metadata, so always check the `side` line
after adding a mod. To change it, edit the `side` line and run `packwiz refresh`.

## Adding a mod

```bash
# Prefer Modrinth, and pin an exact version URL (not just the slug):
packwiz mr add https://modrinth.com/mod/<slug>/version/<version-id>
# CurseForge fallback (some files are API-blocked and can't be downloaded by packwiz):
packwiz cf add <slug-or-url>
```

Then:
1. Check the new `mods/<slug>.pw.toml`: the `filename` must be a 1.20.1 **Forge** build
   (not Fabric/NeoForge), it should be a release rather than an alpha/beta where possible, and
   the `side` must be correct (see above).
2. Accept auto-added dependencies only after checking their sides too.
3. Check compatibility with Create 6.x. Create addons must target Create 6.0+; many older addons
   only work with Create 0.5.x.
4. `packwiz refresh`
5. Update the categorized mod list in `README.md`.
6. Commit with a descriptive message: what the mod is, its version, its side, and why that side
   (see existing commits for the style). Push only when the user asks.

## Removing a mod

```bash
packwiz remove <slug>        # slug = the .pw.toml filename without .pw.toml
packwiz refresh
```

Before removing anything:
- Make sure no other mod depends on it (libraries especially: Moonlight, Zeta, Citadel, Balm,
  TerraBlender, DragonLib, Kotlin for Forge, GlitchCore, libIPN, Searchables, YACL). Look at
  the mod pages or the dependency lists of the remaining mods.
- Removing a **content** mod (`both`) from an existing world deletes its blocks/items/entities
  from that world. Warn the user and suggest a world backup first.
- Orphaned libraries can be removed afterwards if nothing else needs them.
- Update `README.md`, then commit.

## Updating mods

```bash
packwiz update <slug>     # one mod
packwiz update --all      # everything. Review the diff carefully afterwards.
packwiz refresh
```

packwiz does **not** prefer releases over betas. Read the `git diff` after any update.

### JourneyMap must stay on 5.10.x
Create ships compatibility mixins that target JourneyMap 5.x classes. JourneyMap 6.0.0-beta
renamed those classes, so the client crashes at launch (`MixinTransformerError`). After any
update, run `grep filename mods/journeymap.pw.toml`. It must be `journeymap-1.20.1-5.10.x-forge.jar`.
If it is 6.x, re-pin it with `packwiz mr add` and the exact 5.10.x version URL.

## Known decisions / history

- Shaders: Oculus 1.8.0 + Complementary Reimagined (both client). There's no Create/Flywheel
  shader-compat mod: Ocuwheel is CurseForge API-blocked, and "Iris & Oculus Flywheel Compat"
  needs Oculus 1.8.1+. Flywheel falls back to CPU rendering when shaders are on.
- AntiXray is server-only and hides ores in the chunk data sent to clients.

## Environment notes

- `packwiz` is **not** currently installed on this machine (not in PATH). Install it
  (`go install github.com/packwiz/packwiz@latest`, or a release binary into `~/.local/bin`) before
  running the commands above. Never edit hashes in `index.toml`/`pack.toml` by hand to get around this.
- Verify a change with `packwiz list -s client` / `packwiz list -s server`. Ideally, test a
  client launch and a server start before pushing.
